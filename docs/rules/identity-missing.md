# Rule: `identity-missing`

## Problem / Symptom
During `kinema check` (equivalence stage), a component defined in `.v` could not be matched with any footprint on the KiCad PCB layout (`board.kicad_pcb`), or its timestamp does not match the deterministic UUID v5 generated by Kinema.

## Root Cause
1. **Renamed or Renumbered Component**: The component reference designator in `.v` was renamed (e.g. `J1` changed to `J2`), causing Kinema's default UUID derivation to change.
2. **Netlist Not Synced**: A new component was added in `.v`, but the KiCad PCB Editor has not yet imported the newly generated `board.net`.
3. **Import Match Method**: KiCad's netlist importer was executed with reference matching instead of Timestamp / UUID matching.

## Remediation

1. Read the [Component Identity & Refactoring Guide](../guides/identity.md) to learn how to preserve footprint identity.
2. If the component exists on the PCB under a previous reference designator, pin its original UUID:
   ```verilog
   (* id = "<kicad-tstamp-uuid>" *)
   CONN_1X04 J2 (...);
   ```
3. Re-export and import netlist:
   ```bash
   kinema netlist -o board.net
   # In KiCad PCB Editor: File -> Import -> Netlist... (Match by Timestamp / UUID)
   ```
